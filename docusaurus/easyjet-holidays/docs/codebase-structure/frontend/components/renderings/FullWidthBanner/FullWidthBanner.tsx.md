## Imports

The `FullWidthBanner` component utilizes several imports:

- React related:
  - `useEffect` from `react` for handling side-effects.
  - `useInView` from `react-intersection-observer` for detecting when an element is visible in the viewport.

- MobX related:
  - `observer` from `mobx-react` to make the component reactive to state changes.

- Utility and hooks:
  - `useStore` custom hook for accessing MobX stores.
  - `generateGenericValues` utility function for tracking utilities.

- Styling:
  - `classNames` for conditionally joining classNames together.
  - `styles` from local SCSS module for component-specific styles.

- Type definitions:
  - Various types such as `TStores`, `TFullWidthBannerProps`, `ComponentVersion`, `TextAlignmentVariant`, `MediaSize`, `EventTypes`, `EventActions`, `EventCategories` from different model files to type-check the component props and related items.

- Child components and common components:
  - `JSSImage` and `JSSImageNext` for rendering images.
  - `BannerWithKeySellingPoints` and `FullWidthBannerInfo` are child components used based on the banner version.

## Structure

The `FullWidthBanner` component is structured as follows:

1. **Hook Initialization**:
   - `useStore` to get `isEditMode` and `trackEventWithParams` from the store.
   - `useInView` to setup the intersection observer which triggers once when the component comes into view.

2. **Effect Handling**:
   - `useEffect` to handle the tracking of impressions when the banner comes into view.

3. **Conditional Rendering**:
   - Checks if the necessary `fields` are present.
   - Based on the `Version` parameter from `props.params`, it either renders the `BannerWithKeySellingPoints` or constructs a banner layout with optional elements like shards and different alignments.

4. **Dynamic Class Assignment**:
   - Uses `classNames` to conditionally apply CSS classes based on the `TextAlignment`, `Version`, and `isEditMode`.

5. **Image Handling**:
   - Conditionally renders images using `JSSImage` or `JSSImageNext` based on the edit mode.

6. **Information Display**:
   - Renders the `FullWidthBannerInfo` component which likely displays textual information or additional details about the banner.

## Logic

- **Tracking Logic**:
  - When the banner component first appears in the viewport (`inView`), an event is tracked using `trackEventWithParams`. This event logs the type as `EventTypes.GenericEvent` and includes details such as action, category, label, and type, with additional generic values generated by `generateGenericValues`.

- **Edit Mode**:
  - In edit mode, the component renders a different set of styles and potentially different content to facilitate easier content management in a CMS environment.

- **Responsive and Conditional Styling**:
  - The component adjusts its layout and styling based on the `Version` and `TextAlignment` properties. This includes adjustments for text alignment (left or default), slim versions of the banner, and optional mirrored shard appearances.

- **Component Reusability and Composition**:
  - Depending on the `Version`, the component either delegates rendering to `BannerWithKeySellingPoints` or handles it internally, showing flexibility and reusability in component architecture.

This component is designed to be highly configurable and responsive, adapting to various content types and styles as dictated by the props it receives.
