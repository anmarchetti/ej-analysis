## Structure

The code defines two main functions to generate mock properties and fields for a full-width banner component:

- **`getMockFullWidthBannerProps`:**
  This function returns an object of type `TFullWidthBannerProps`, which includes:
  - `fields`: Generated by calling `mockFullWidthBannerMockFields()`.
  - `params`: An object containing various configuration parameters such as theme, color, text alignment, font style, component version, and title font size.
  - `rendering`: An empty object, potentially used for additional rendering data in a real-world scenario.

- **`mockFullWidthBannerMockFields`:**
  This function returns an object of type `IFullWidthBannerFields`, which represents the content fields of the banner. It includes:
  - `Title`, `TrackingTitle`, `Description`: Text fields created using `mockSitecoreField`.
  - `Image`: An image field created using `mockSitecoreImageField`.
  - `CTA`: A link field created using `mockSitecoreLinkField`.
  - `PillText`: A text field for a small decorative or informative "pill" element.
  - `IsLuxuryBadge`: A boolean field to indicate if a luxury badge should be displayed.
  - `KeySellingPoints`: A composite field containing an array of items, structured using `mockSitecoreCompositeField`.

## Logic

The primary logic of the script revolves around creating mock data for testing the full-width banner component. This is achieved by:

- Defining default values and structures for the banner's properties and fields using mock utility functions. These functions simulate the behavior of real Sitecore fields, which is crucial for unit testing in a development environment where Sitecore services are not available.
- Structuring the mock data to conform to the expected interfaces (`TFullWidthBannerProps` and `IFullWidthBannerFields`), ensuring that any component consuming these props can operate as if it were receiving data from an actual Sitecore backend.
- Providing flexibility in the banner's appearance and behavior through parameters like `CTATheme`, `PillColour`, `TextAlignment`, etc., which can be easily adjusted in the mock for testing different configurations.

This approach facilitates the development and testing of the full-width banner component independently of the backend, speeding up front-end development and ensuring component robustness through comprehensive testing.
