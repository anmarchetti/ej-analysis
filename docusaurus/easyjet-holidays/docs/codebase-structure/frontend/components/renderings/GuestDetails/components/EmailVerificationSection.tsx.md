## Imports

The `EmailVerificationSection` component utilizes several imports to function properly:

- **mobx-react**: Imports `observer` to make the component reactive to MobX state changes.
- **useStore**: Custom hook from `frontend/hooks/useStore` to access MobX stores.
- **IHolidaysStores**: Interface from `frontend/store/holidays` that defines the shape of the holiday-related stores.
- **SvgUserFilled**: A React component from `frontend/components/icons-new/UserFilled` representing a user icon.
- **GuestDetailsBlock**: A component from the local `section` directory used to display details for each guest.
- **EmailVerification**: A component from the local directory to handle email verification logic.
- **styles**: Module CSS for styling from `./GuestSection.module.scss`.

## Structure

The `EmailVerificationSection` is a functional React component that accepts `IEmailVerificationSectionProps` as props, which includes:

- **hasSignInPrompt**: A boolean indicating whether to display a sign-in prompt.

The component is structured to render three lists of `GuestDetailsBlock` components for different types of guests: adults, children, and infants. Each list is generated by mapping over arrays (`adults`, `children`, `infants`) obtained from a custom hook `useStore`.

### JSX Structure

The component returns a single `<div>` element with a class from the imported styles. Inside this `<div>`, it maps over the `adults`, `children`, and `infants` arrays to render `GuestDetailsBlock` components for each guest. Each `GuestDetailsBlock` contains:

- A unique `key` and `id` constructed from the guest's details and index.
- `title` and `secondaryText` obtained from store functions `getPrimarySectionText` and `getSecondarySectionText`.
- An `icon` displayed using the `SvgUserFilled` component.
- A `<EmailVerification>` component as a child for adults, which also receives `hasSignInPrompt` as a prop.

## Logic

### Store Hook

The `useStore` hook is used to extract necessary details from the MobX store:

- **adults, children, infants**: Arrays representing different types of guests.
- **getPrimarySectionText, getSecondarySectionText**: Functions to retrieve text based on the guest's details.

These values are destructured from the object returned by the `useStore` hook, which itself takes a function to specify which parts of the store to access.

### Rendering Logic

For each type of guest (adults, children, infants), the component maps over their respective arrays to create `GuestDetailsBlock` components:

- For **adults**, it also includes an `EmailVerification` component and uses properties `isLead` and `disabled` to control the behavior based on whether the guest is the lead guest.
- For **children** and **infants**, the blocks are always disabled (no email verification or lead guest functionality).

### Reactivity

The component is wrapped with `observer` from `mobx-react`, making it reactive to changes in the MobX store. This ensures that any updates to the guest details in the store will automatically trigger a re-render of the component, keeping the UI consistent with the state.
